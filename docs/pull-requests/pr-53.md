# [PR 53](https://github.com/exoma-ch/brother-printer/pull/53) chore(versioning): derive package versions from git tag via hatch-vcs (#52)

## Summary

Closes #52. Derives both package versions from the git release tag via **hatch-vcs**, so the tag the release workflow already creates is the single source of truth. This unblocks the 0.2.0 release.

Previously both `pyproject.toml` files hardcoded `version = "0.1.0"` and the driver hardcoded `__version__`, which the CHANGELOG-driven release workflow never updates — so after a release `brother-ptouch-driver --version` / `brother-ptouch-label --version` (via `click.version_option(package_name=...)`) would keep reporting the old version.

## Changes

- Both packages declare `dynamic = ["version"]`, add `hatch-vcs` to build requires, and set `[tool.hatch.version] source = "vcs"` with `raw-options = { root = "../.." }` (packages live in subdirectories of the git root).
- `brother_ptouch_driver.__version__` now reads `importlib.metadata.version(...)` instead of a literal.
- Regenerated `uv.lock` (workspace members are now `dynamic`).
- `test_version` compares `__version__` against installed metadata instead of a hardcoded string.
- CHANGELOG `Unreleased → Changed` entry added.

## Behaviour

- Off-tag builds report a dev version (e.g. `0.2.1.devN+g<sha>`); a clean `X.Y.Z` is reported only at the exact tag.
- Lockstep: both packages derive from the same `X.Y.Z` tag (matches the current de-facto model).

## Verification

- `uv sync` clean; `brother-ptouch-driver --version` and `brother-ptouch-label --version` report the computed version.
- `just test` → 321 passed, 10 skipped; `just lint` clean.
