# [PR 38](https://github.com/exoma-ch/brother-printer/pull/38) fix: guard BASH_SOURCE[0] so scripts survive curl | bash under set -u

## Description

`packaging/scripts/setup-usb.sh` is documented to be installed via `curl -fsSL .../setup-usb.sh | bash`. When run that way, bash reads the script from stdin so the `BASH_SOURCE` array is empty, and under `set -u` the unguarded `${BASH_SOURCE[0]}` reference on the `SCRIPT_DIR=` line prints `bash: line 15: BASH_SOURCE[0]: unbound variable`. The failure was masked (it occurs inside a command substitution, so the rule was still fetched from GitHub), making it fragile rather than benign.

This PR guards `${BASH_SOURCE[0]}` with a `$0` default so the piped install runs cleanly, and applies the same hardening to the other helper scripts that use the same pattern. A parametrized regression test reproduces the exact failure mode for all affected scripts.

## Changes Made

- `packaging/scripts/setup-usb.sh` -- guard `${BASH_SOURCE[0]:-$0}` in the `SCRIPT_DIR` derivation (the actual bug, documented `curl | bash` path)
- `docs/vendor/convert.sh`, `docs/vendor/fetch.sh` -- same hardening
- `.devcontainer/scripts/post-create.sh`, `post-attach.sh`, `initialize.sh`, `version-check.sh` -- same hardening
- `packaging/tests/test_setup_usb.py` -- new parametrized regression test that pipes each script's `SCRIPT_DIR=` assignment into bash via stdin (mimicking `curl | bash`) and asserts no `unbound variable` error
- `pyproject.toml` -- register `packaging/tests` as a pytest testpath
