# [PR 35](https://github.com/exoma-ch/brother-printer/pull/35) fix: normalize CHANGELOG end-of-file for release 0.1.0

## Summary

Normalize `CHANGELOG.md` to end with exactly one trailing newline.

The `prepare-release` `Prepare CHANGELOG (freeze + reset)` step (the `prepare-changelog prepare` tool) wrote the file with a double trailing newline. Because that commit was pushed via the GitHub Contents API, it bypassed pre-commit, so the malformed EOF landed on `release/0.1.0` undetected and only surfaced as a `Lint & Format` failure (`end-of-file-fixer`) on release PR #34.

This unblocks PR #34 CI. The underlying tool bug is reported upstream against `vig-os/devcontainer`.

## Test plan

- [x] `uv run pre-commit run end-of-file-fixer --files CHANGELOG.md` passes
- [ ] PR #34 `Lint & Format` / `CI Summary` go green after merge
