# [PR 62](https://github.com/exoma-ch/brother-printer/pull/62) fix(renovate): point the shared preset at this repository (#59)

## Description

`renovate.json` extended `github>OWNER/REPO//.github/renovate-default` — the
literal scaffold placeholder. Renovate could not resolve the shared preset
(`Cannot find preset's package`) and **stopped opening dependency PRs for this
repository as a precaution**, which is how the breakage surfaced as #59.

The devkit `0.3.4` scaffold this repo was created from predates `install.sh`'s
`--repo` flag, so the placeholder was never substituted. The preset file itself
was always present and correct at `.github/renovate-default.json`; only the
reference to it was wrong.

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- `renovate.json`: `OWNER/REPO` → `exoma-ch/brother-printer`

That is the whole fix. `renovate.json` is a **preserved** file, so no scaffold
run repairs it — it has to be a hand edit, which is why #60's upgrade left it
alone.

### Why this is stacked on #61

> **Base is `feature/60-upgrade-devkit-direnv-mode`, not `dev`. Merge after
> #61, or retarget to `dev` once #61 lands.**

The `0.3.4` git hooks in `dev` refuse any commit made outside the dev container
(`IN_CONTAINER != true`) and carry a `#!/bin/bash` shebang that cannot even
execute on a NixOS host. So this one-line fix was literally uncommittable from
`dev` without pulling the retired ~1.8 GB Debian image. devkit `1.18.0` sanctions
`IN_NIX_SHELL` as well, so #61 unblocks it. CI runs on this stack because
`1.18.0` widened the `pull_request` base filter to `'**'`.

The alternative was to reorder, which is what happened: #61 went first.
