# [PR 48](https://github.com/exoma-ch/brother-printer/pull/48) feat(label): add --replicate option for cable-wrap flag labels

## Description

Adds a `--replicate N` option (alias `--repeat`) to `brother-ptouch-label` that repeats the text along the axis **perpendicular to its reading direction**, producing a single label that stays legible when wrapped around a cable — the "cable-wrap / flag" use case, especially useful with flexible-ID (TZe-FX) tapes. Also supports `--replicate auto` to fill the tape with as many copies as fit at a given font size. Closes #45.

## Type of Change

- [x] `feat` -- New feature

### Modifiers

- [ ] Breaking change (`!`) -- backward compatible; default `N=1` is a no-op.

## Changes Made

- **`render_text(..., replicate=1)`** in `text.py`: when `N > 1`, renders one unit and tiles it `N` times.
  - **Without `--rotate`** (text reads along the length): copies stack across the tape **width**; an optional `print_extent` is threaded through `max_font_size()` and the horizontal renderer so each copy is auto-fitted to its own `print_area_pins / N` band. Final image height stays exactly `print_area_pins`.
  - **With `--rotate`** (text reads across the width): copies repeat along the **feed** axis at full width.
  - **`--replicate auto`** (aliases `fill`/`max`): `_resolve_replicate()` derives the max copy count from the per-copy block height vs. the tape printable height (no rotation), or tiles along the feed up to `--width` (rotated). Requires an explicit `--font-size` (and `--width` when rotated); errors clearly otherwise.
  - Refactored shared font-size resolution into `_resolve_font_size()`; added `_tile_vertical()` / `_tile_horizontal()` helpers. `replicate=1` returns the original single render byte-for-byte (golden fixtures unchanged).
- **`printing.py`** and **CLI** thread the new `replicate` parameter; CLI exposes `--replicate/--repeat` via a custom param type accepting an integer or `auto`.
- Errors clearly when `N` exceeds the printable rows, when `N < 1`, or for unknown string values.

## Changelog Entry

### Added
- **`brother-ptouch-label --replicate N` (alias `--repeat`) for cable-wrap "flag" labels** ([#45](https://github.com/exoma-ch/brother-printer/issues/45))
  - Repeats the text `N` times along the axis perpendicular to its reading direction, so a single label stays legible when wrapped around a cable (useful with flexible-ID TZe-FX tapes)
  - Without `--rotate`, copies stack across the tape width and each is auto-fitted to `print_area_pins / N`; with `--rotate`, copies repeat along the feed axis at full width
  - Accepts `--replicate auto` to fit as many copies as the tape and font size allow (needs `--font-size`, plus `--width` when combined with `--rotate`)
  - Defaults to `1` (no replication), so existing renders are unchanged

## Testing

- `just lint` -- clean
- `just test` -- full suite green (115 label tests; driver suite unaffected)
- New unit tests cover: `replicate=1` byte-for-byte no-op, copies stacked across the width, per-copy font shrink, rotated copies repeat along the feed, `auto` fills the width / requires font-size / rotated-auto requires width, too-many-copies and `< 1` / invalid-string error paths, and end-to-end raster jobs. CLI tests cover `--replicate`, `--repeat`, `--replicate auto`, and invalid-value rejection.
- **Hardware-verified** on a PT-E920BT with 24 mm Flexible ID tape:
  - `brother-ptouch-label "Flex ID" --font-size 40` -- single label.
  - `brother-ptouch-label "Flex ID" --font-size 40 --replicate 2` -- two copies across the width.
  - `brother-ptouch-label "Flex ID" --font-size 40 --replicate auto` -- 8 copies, tape fully filled.
