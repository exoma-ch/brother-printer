# [PR 44](https://github.com/exoma-ch/brother-printer/pull/44) fix(workspace): preserve quoting in just CLI recipes (#42)

## Summary

Fixes #42 — `just` recipes lost argument quoting, so any label text containing a space was split into multiple CLI arguments and failed.

```console
$ just label "Flex ID"
uv run brother-ptouch-label Flex ID
Error: Got unexpected extra argument (ID)
```

## Root cause

The recipes forwarded arguments via raw textual interpolation, `uv run brother-ptouch-label {{ args }}`. `{{ args }}` is a plain text substitution, so `just label "Flex ID"` expanded to the literal line `uv run brother-ptouch-label Flex ID`; the shell then word-split it into two arguments. The `brother-ptouch-label` CLI was correct all along — it takes a single `TEXT` argument and rightly rejected the second.

## Fix

Enable `set positional-arguments` and forward `"$@"` (real shell positional parameters, which preserve quoting) instead of `{{ args }}` in every `*args` forwarding recipe: `discover`, `printer-status`, `tapes`, `print`, `label`, `setup-usb`.

## Verification

Non-destructive (renders a PNG instead of printing, with explicit tape so no printer is queried):

```console
$ just label "Flex ID" --tape 12mm -o /tmp/flexid.png
Wrote /tmp/flexid.png.        # exit 0 — "Flex ID" received as a single argument
```

- Before the fix this same command errored with `Got unexpected extra argument (ID)`.
- Regression-checked no-arg recipes (`just tapes`) still work under `set positional-arguments`.
