# [PR 64](https://github.com/exoma-ch/brother-printer/pull/64) feat(setup-usb): support NixOS hosts and add a one-off USB grant (#63)

## Description

`packaging/scripts/setup-usb.sh` could not grant non-root USB access on a NixOS
host: libusb dispatch found no `apt`/`dnf`/`pacman`/`zypper` and installed
nothing, the udev rule copy targeted `/etc/udev/rules.d` (a read-only symlink
into the Nix store), and `plugdev` neither exists nor can be created from
outside the system configuration. The script is the repo's published answer to
"how do I make the printer reachable", so a NixOS user got a warning and no
working path.

It now detects NixOS and takes a different path, and a new `--one-off` flag
makes the chmod grant available (and scriptable) on any distribution.

## Changes Made

**`packaging/scripts/setup-usb.sh`**

- Detects NixOS via `/etc/NIXOS` or `ID=nixos` in `/etc/os-release`.
- Skips the package-manager step there, pointing at the dev shell
  (`nix develop` / `direnv allow`) or the user's own profile for `libusb`.
- Locates the connected `04f9:224b` device through sysfs
  (`/sys/bus/usb/devices/*/{idVendor,idProduct,busnum,devnum}`), derives
  `/dev/bus/usb/<bus>/<dev>`, and offers to `chmod` it after confirming — the
  one grant the script can genuinely make, and it saves hand-deriving a path
  that changes on every replug.
- Prints the rule to declare in the system configuration rather than pretending
  to install it.
- New `--one-off` grants access on the connected printer and does nothing else
  (no libusb, no udev rule, no group); `-y`/`--yes` skips the confirmation.
  Confirmation declines when stdin is not a terminal rather than blocking on a
  prompt nobody can answer.
- `main` is guarded so the functions can be sourced, and host paths come from
  overridable `SETUP_USB_*` variables — that is what lets both paths be tested
  without a NixOS host. The conventional path is unchanged.

**The printed rule uses `GROUP`/`MODE`, not `TAG+="uaccess"`** — a correction to
what #60 documented. On NixOS the tag is applied but nothing consumes it: the
`RUN{builtin}+="uaccess"` that installs the ACL ships in systemd's
`71-seat.rules` / `73-seat-late.rules`, neither of which NixOS assembles into
`/etc/udev/rules.d`. `udevadm info` shows the tag, `getfacl` shows no ACL, and
`open()` still fails. Verified on the host in #63.

**Docs** — `docs/install/linux-usb.md` gains a `## NixOS hosts` section (libusb,
the declarative rule, the `uaccess` caveat, the group that
`services.udev.packages` additionally needs because the shipped rule grants
`GROUP="plugdev"`, and the one-off grant). Quick setup, Prerequisites and the
dev-shell section link to it instead of restating it, and the dev-shell
section's `uaccess` recommendation is gone. `99-brother-ptouch.rules` records
that `plugdev` membership is the load-bearing grant and the `uaccess` tag only
adds something where systemd's seat rules are in the assembled rule set.

Not done, by design: no NixOS module / flake output exposing the rules package
(the issue parks that as a larger surface worth its own discussion), and the
script still does not write to a host's NixOS configuration.

```markdown
- **`packaging/scripts/setup-usb.sh` supports NixOS hosts, and gained a one-off grant** ([#63](https://github.com/exoma-ch/brother-printer/issues/63))

It needs no rebuild and is lost on replug, which is all a single hardware check wants, and it works on any distribution, not just NixOS; `--yes` skips the confirmation for unattended use. Privileged prompts decline when stdin is not a terminal instead of blocking on a prompt nobody can answer
  - [docs/install/linux-usb.md](docs/install/linux-usb.md) gains a NixOS section, and its development-shell section no longer recommends the inert `uaccess` rule. `packaging/udev/99-brother-ptouch.rules` records that `plugdev` membership is the load-bearing grant and that the `uaccess` tag adds something only where systemd's seat rules are part of the assembled rule set
  - The conventional-distribution path is unchanged and now has regression tests. Host paths come from overridable `SETUP_USB_*` variables and `main` is guarded so the script's functions can be sourced, which is what lets both paths run end to end against a fake host tree on any Linux host — including a CI runner, which is not NixOS
```

## Testing

- [x] Tests pass locally (`just test`) — 375 passed, 10 skipped (hardware)
- [x] Manual testing performed (describe below)

New `packaging/tests/test_setup_usb_nixos.py` (20 tests with the existing file):
NixOS detection via marker and via bare/quoted `ID=nixos`; sysfs node discovery
including the zero-padded path and the no-printer case; the declarative rule
(asserted on the rule line itself, so a `uaccess` regression fails); the
end-to-end NixOS run (no package manager, no `udevadm`, no `usermod`, empty
udev dir); the one-off grant with and without confirmation; and regression
tests that a conventional host still installs the rule and joins `plugdev`.

The tests drive the real script against a fake host tree through the
`SETUP_USB_*` hooks, with stub executables ahead on `PATH`, so they pass both on
a NixOS workstation and on a non-NixOS CI runner.

### Manual Testing Details

Run on a real NixOS host (`26.05`) with a PT-E920BT connected:

- `./packaging/scripts/setup-usb.sh` — reports NixOS, skips libusb with the dev-shell
  pointer, finds the printer at `/dev/bus/usb/003/019` (matching sysfs:
  `3-2`, `busnum=3`, `devnum=19`), declines the grant non-interactively and prints the
  exact `sudo chmod` command, then prints the declarative rule. Nothing was installed
  or modified.
- `./packaging/scripts/setup-usb.sh --one-off` — same discovery, chmod offered and
  printed, no other action.
- `shellcheck -x` and the full `prek run --all-files` suite are green.

The only step not exercised against the real host is the `sudo chmod` itself
(covered by the fake-host tests), since it needs an interactive password.

## Additional Notes

The `uaccess` finding has a wider edge the issue flags and this PR does not
close: `99-brother-ptouch.rules` carries `TAG+="uaccess"` alongside
`GROUP="plugdev"` for conventional distributions, where the seat rules are
present and the tag does work — the `plugdev` fallback is what has been carrying
it regardless. The rule file now says so; whether to keep the tag at all is a
separate question.
