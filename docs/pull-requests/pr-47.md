# [PR 47](https://github.com/exoma-ch/brother-printer/pull/47) feat(imaging): confine self-laminating tape printing to the white band

## Description

Self-laminating TZe-SL tape (e.g. TZe-SL251, TZe-SL261) has a printable white strip at one edge plus a clear laminate flap that wraps the cable. Today every print path centres content across the full tape width, so on self-laminating tape content lands on the clear flap and the label is misaligned. This confines printing to the narrow white band and centres content there, automatically.

Closes #41.

## Type of Change

- [x] `feat` -- New feature

### Modifiers

- [ ] Breaking change (`!`) -- backward-compatible; behaviour only changes when self-laminating tape is detected.

## Changes Made

- **Detection.** Self-laminating media is recognised from the live status reply via `MediaType.SELF_LAMINATING` (`0x16`) or `TapeColor.WHITE_SELF_LAMINATING` (`0x80`) — both signals appear in the field (#39).
- **Band geometry.** The white strip is a fixed physical height (~9.8 mm, bounded by the minimum cable circumference), ≈139 pins at 360 dpi **rounded up to a tidy 140 px** — the same on 24 mm and 36 mm tape. New helpers `self_laminating_band_pins`, `is_self_laminating`, `effective_print_pins` (exported on the library API).
- **Imaging pipeline (single source of truth).** `image_to_raster` / `resize_to_tape_width` / `pack_raster_lines` take an `effective_height`; a band-height image packs anchored at the white-strip (`right_pins`) edge, leaving the clear-flap pins unprinted. `print_image`/`print_strip` derive it from the status they already query — so **direct PNG, text, and strip/CSV all benefit**.
- **Text quality.** The label renderer (`render_text`/`max_font_size`) renders directly at the band height, so text is sized for the band rather than downscaled. The label CLI reads media type from one status query and passes the band height through.
- **`info tapes`.** `brother-ptouch-driver info tapes` now reports the band as a `self-laminating  140 px` row alongside the per-width print areas.
- **Docs.** README feature + quick-start note, `docs/vendor/tze-tape-widths.md` self-laminating band section, CHANGELOG entry.

PNG fit semantics are otherwise unchanged: across the tape the flap is padded (unprinted); within the band a non-band-height PNG still requires `--scale` rather than auto-downscaling (preserves QR sharpness).

### Manual Testing Details

Run on this branch against a PT-E920BT with a **36 mm TZe-SL261** self-laminating cartridge loaded:

```
$ brother-ptouch-driver status
  Tape:   36 mm
  Color:  White
  Media:  Self Laminating          # 0x16 -> band path engaged

$ brother-ptouch-driver info tapes
  ...
  36 mm            454 px
  self-laminating  140 px

$ brother-ptouch-label "Self-laminating\n Cable diam. 3.0 to 10.4mm"
  Printed 42667 bytes.
```

The renderer auto-detected self-laminating media and produced a 140 px (~9.8 mm) band render instead of the full 454 px tape height — both lines centred in the white strip, clear flap left unprinted, with no `--margin-bottom` workaround.
